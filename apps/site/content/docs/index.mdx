# AEX documentation

AEX runs multi-message agent work in a durable session with one isolated
workspace. Start with the TypeScript SDK; the same public contract is available
to the CLI and HTTP clients.

## Quickstart

Install `@aexhq/sdk`, provide your AEX workspace key and a registered provider
credential, then create a session and send a message.

```ts
import { Aex, assertId } from "@aexhq/sdk";

const aex = new Aex(process.env.AEX_WORKSPACE_API_KEY!);
const session = await aex.sessions.sessionCreate({
  body: {
    provider: "openai",
    model: process.env.AEX_MODEL!,
    providerCredentialId: assertId(
      "provider_credential",
      process.env.AEX_PROVIDER_CREDENTIAL_ID,
    ),
  },
  idempotencyKey: crypto.randomUUID(),
});

await aex.sessions.sessionMessageSend({
  sessionId: session.id,
  body: { text: "Inspect the repository and report the failing tests." },
  idempotencyKey: crypto.randomUUID(),
});
```

Provider credentials are encrypted BYOK resources. A session pins one exact
credential; AEX does not supply a managed model key at launch.

## Sessions

A session accepts one text message at a time and keeps its workspace across
messages. Idle compute suspends after 180 seconds and resumes for the next
message or live-file call. The hard eight-hour workspace lifetime is never
extended by suspension.

Termination destroys the MicroVM and its live files while retaining session
metadata, messages, accounting, and telemetry. There is no snapshot, fork,
trash, or restore path at launch.

## Files and tools

Registered workspace files are durable inputs copied into the MicroVM at
session creation. Live session files exist only in that generation and support
exact list, stat, resumable upload, and digest-verified download.

The launch model-tool surface is `read_file`, `edit_file`, `write_file`, and
Bash. Instructions, skills, tool material, and MCP configuration can be
ordinary workspace files. Typed observations and OpenTelemetry remain durable
independently of session execution.
