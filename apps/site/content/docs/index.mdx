# AEX documentation

An AEX session is a durable multi-message conversation. It owns committed
message history, an exact model, native subagents, frozen file mounts, tool
effects, sandbox lifecycle, usage facts, and telemetry. Send text directly to
the session and point the model to mounted files by path. There is no public run
resource, file revision API, or attachment field.

## Quickstart

Install `@aexhq/sdk`, then provide one workspace API key and the provider key
that this session will encrypt and own.

```ts
import { Aex, newId } from "@aexhq/sdk";

const aex = new Aex({ apiKey: process.env.AEX_WORKSPACE_API_KEY! });
const session = await aex.sessions.sessionCreate({
  body: {
    provider: "openai",
    model: process.env.AEX_MODEL!,
    providerApiKey: process.env.AEX_PROVIDER_API_KEY!,
  },
  idempotencyKey: crypto.randomUUID(),
});

const committed = (async () => {
  for await (const frame of aex.sessions.sessionMessagesStream({
    sessionId: session.id,
  })) {
    if (frame.kind === "committed" && frame.message?.role === "assistant") {
      return frame.message;
    }
  }
  throw new Error("message stream ended before the assistant committed");
})();

await aex.sessions.sessionMessageSend({
  sessionId: session.id,
  body: { text: "Inspect the repository and report the failing tests." },
  idempotencyKey: crypto.randomUUID(),
});
console.log(await committed);

await aex.sessions.sessionTerminate({
  sessionId: session.id,
  body: {},
  operationId: newId("operation"),
});
```

The provider key is admitted only for that session, encrypted before durable
storage, and never returned. Supported provider families are OpenAI, Anthropic,
DeepSeek, xAI, Meta, Moonshot AI, and Alibaba. Choose an exact provider-native
model that supports the tools or structured output your session needs.

## Sessions

Session creation durably starts eager sandbox preparation in the background and
returns without waiting for provisioning, file materialization, or suspension.
Preparation progress appears in telemetry. A sandbox tool call waits for the
exact generation to become ready and resumes it when necessary.

The sandbox is enabled by default. With `sandbox.enabled: false`, AEX allocates
no sandbox and sandbox-only tools return a structured error the model can
handle. Remote HTTP MCP can still run without a sandbox; mounted files,
sandbox-process MCP, and pinned sandbox packages require one.

Cancel stops the active message and returns the session to idle. Terminate
destroys sandbox compute while retaining committed messages and telemetry.
Delete irreversibly removes session-owned content through an idempotent
maintenance flow; independent workspace files remain. A launch session lasts
at most eight hours and admits at most 12 child identities with maximum depth 3.

## Files and mounts

Workspace files expose one current value per logical name. Replace that value
with inline text or bytes, an HTTPS URL, or a direct multipart upload. Session
creation resolves selected names once and freezes their sandbox paths, so a
later workspace overwrite cannot mutate an existing session.

```ts
await aex.workspaceFiles.put(
  "agent-guide",
  { type: "text", text: "Run the focused tests before changing source." },
  { mediaType: "text/markdown" },
);

const fileSession = await aex.sessions.sessionCreate({
  body: {
    provider: "openai",
    model: process.env.AEX_MODEL!,
    providerApiKey: process.env.AEX_PROVIDER_API_KEY!,
    registered: {
      mounts: [{ name: "agent-guide", path: "/workspace/AGENTS.md" }],
    },
  },
  idempotencyKey: crypto.randomUUID(),
});
```

Use `aex.workspaceFiles.upload(name, bytes)` for images, PDFs, video, archives,
and other arbitrary bytes. User messages remain text-only: tell the model which
file or directory under `/workspace` to inspect. Downloads verify the exact
length and SHA-256 digest returned by AEX.

## Tools, MCP, and structured output

The built-in surface is `bash`, `read_file`, `edit_file`, `write_file`,
`mcp_call`, `storage_persist`, `create_subagent`, `wait_subagents`, and
`stop_subagent`. Large tool results keep a bounded preview in the message and
the full result at a sandbox path. `storage_persist` is the provider-safe wire
name for the product tool `storage.persist`, which publishes a sandbox file as
the latest workspace value.

Configure remote Streamable HTTP or sandbox-process MCP when creating the
session. MCP headers and process environment values are session-encrypted and
never returned. Native JSON Schema output is available only when the selected
provider and model support it; AEX does not present prompt emulation as strict
structured output.

```ts
const toolSession = await aex.sessions.sessionCreate({
  body: {
    provider: "openai",
    model: process.env.AEX_MODEL!,
    providerApiKey: process.env.AEX_PROVIDER_API_KEY!,
    mcpServers: [{
      name: "docs",
      transport: { kind: "remote_http", url: "https://mcp.example.com" },
    }],
  },
  idempotencyKey: crypto.randomUUID(),
});

await aex.sessions.sessionMessageSend({
  sessionId: toolSession.id,
  body: {
    text: "Inspect the docs tool and return the affected files.",
    responseFormat: {
      kind: "json_schema",
      schema: {
        type: "object",
        properties: { files: { type: "array", items: { type: "string" } } },
        required: ["files"],
        additionalProperties: false,
      },
    },
  },
  idempotencyKey: crypto.randomUUID(),
});
```

Committed messages preserve provider-neutral text, tool-call, and tool-result
parts. Independent tool effects may run concurrently, but their results commit
in the original model call order.

## Streaming and telemetry

The message stream uses bounded NDJSON frames. Preview frames are best effort
and never delay model work; `gap` reports pressure or loss, `committed` exposes
durable authority, and `reconcile` replaces speculative preview state.

The telemetry stream carries trusted assistant, tool, runtime, log, span,
usage, gap, and heartbeat frames. AEX retains compressed immutable segments for
replay and verified download after the live connection ends. Provider/model
token usage follows a separate trusted billing path and is never inferred from
guest telemetry.

## Credentials and billing

Central bootstrap, API-key, and billing routes require a GitHub dashboard
session. Regional session and file routes require a workspace API key. One
`Aex` client may hold both credentials, but it sends each only to its owning
plane.

```ts
const account = new Aex({
  dashboardSession: process.env.AEX_DASHBOARD_SESSION!,
  apiKey: process.env.AEX_WORKSPACE_API_KEY!,
});

const [balance, cards, usage] = await Promise.all([
  account.billing.billingBalanceGet(),
  account.billing.billingPaymentMethodsList(),
  account.billing.billingUsageGet({ query: { category: "runtime", limit: "20" } }),
]);

const topUp = await account.billing.billingTopUpCheckoutCreate({
  body: { amountCents: "2000" },
  idempotencyKey: crypto.randomUUID(),
});
console.log(balance, cards, usage, topUp.url);
```

Card entry and top-up happen on hosted pages. AEX exposes only saved-card
display metadata, prepaid balance, immutable transactions, and usage filtered
by session, provider, model, or category. Raw card details never enter the AEX
API.
