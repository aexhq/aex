# Retries and idempotency

The SDK retries only retry-safe transport failures and responses covered by its
bounded policy. Disable transport retries with `retry: false` when a caller
owns the policy.

Mutation retries require stable identity. Session and message admissions use
`Idempotency-Key`; durable operations use an `Aex-Operation-Id` generated by
the SDK unless the caller supplies one.

```ts
const { run } = await session.messages.send("Continue.", {
  idempotencyKey: "continue-2026-07-30"
});
await run.result();
```

Reusing one idempotency key with different bytes is an explicit conflict.
