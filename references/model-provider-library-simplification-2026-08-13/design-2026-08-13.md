# Amended design and owner decisions (2026-08-13)

This document supersedes the affected sections of
[`model-provider-library-simplification-2026-08-12.md`](../model-provider-library-simplification-2026-08-12.md):
decisions 1, 6, and 7, the "Catalog trust is a separate decision" section, and
the open questions. Everything else in the original proposal stands. Every
disposition below was owner-approved 2026-08-13.

Companion documents: the [folder index](README.md), the four
[spike reports](spikes/rig-streaming-retry.md) — rig streaming/retry,
[models.dev codegen](spikes/models-dev-codegen.md),

## Owner dispositions of review findings

| # | Finding (summary) | Disposition |
| --- | --- | --- |
| F1 | rig has no `max_retries = Some(0)` API; SSE reconnect looked infinite | **Resolved by spike.** rig 0.41.0's OpenAI-compatible streaming is already zero-reconnect: the event-source retry machinery exists but is unreachable through the public provider path — the streamer breaks on the first error item and closes the event source. One error, then termination. No custom `CompletionModel`, no fork, no acceptance of re-sends. |
| F2 | Deleting the 429/503 in-call retry would kill sessions on transient overload | **Keep the retry, ours.** rig offers nothing; the new router implements a bounded retry loop (see revised decision 7). |
| F3 | `NotSent`/`PossiblySent`/`ResponseStarted` still consumed by the brain; router must keep producing them | **Accepted as-is.** We cannot deal with possibly-sent anyway; the policy simplifies to bounded retry, then stop or success. `DispatchProof` values become best-effort assignments: `NotSent` for pre-send failures only, `PossiblySent` for rig send errors, `ResponseStarted` on first stream item. The brain, `ProviderPort`, and `DispatchTicket` are untouched. |
| F4 | Port-level `StreamBudget` + byte/ledger bounds | **Delete.** No stream bounds at all — no byte caps, no idle timeout, no ledger, no `StreamBudget::narrowed_to`. The port signature keeps its `StreamBudget` parameter (seam stability) but the new adapter ignores it; the port struct itself is later deletable in a clean-cut. The mux's per-activation stream-buffer reservation is removed with it. |
| F5 | Generated artifact must feed more than five fields (capabilities, max_tools, cacheable prefix, reasoning-replay) | **Delete what the deletion enables.** The generated row carries only `provider, model, context_window_tokens, max_output_tokens, tools, parallel_tools, dialect_class`. `max_tools` and `min_cacheable_prefix_tokens` become per-dialect-class compiled constants; `requires_reasoning_token` becomes a per-dialect-class function; `DurableOperationSupport` is always `None` and moves to `aex-brain-domain`. `Capability`/`CapabilitySet` shrink to a 2-bit set so the surviving `has(Capability::Tools)` call sites compile unchanged. |
| F6 | Naming/routing corrections (`vercel` vs `vercel_ai_gateway`, `moonshot`, npm classes, missing vercel base URL) | **Accepted.** The dialect map uses models.dev `npm` with four classes: `@ai-sdk/openai` → NativeOpenai, `@ai-sdk/anthropic` → NativeAnthropic, `@ai-sdk/google` → NativeGemini, everything else (`@ai-sdk/openai-compatible`, `@openrouter/ai-sdk-provider`, `@ai-sdk/gateway`) → OpenAiCompatible. Vercel's base URL is a compiled constant (`https://ai-gateway.vercel.sh/v1`); the `vercel` provider keeps its public wire id `vercel_ai_gateway`. |
| F7 | Receipts lose request ids on errors and rate-limit header parsing | **Accepted.** `ProviderReceipt.provider_request_id` is `None` for failed attempts; `retry_after`/rate-limit feedback becomes `None`. |
| F8 | Credential hand-off shape | **Recommendation accepted:** one shared pooled `reqwest::Client` per runtime, injected into a per-dispatch rig client (`http_client()` builder injection); the key is passed by borrow (`key.as_str()` → `impl Into<BearerAuth>`), so no AEX-owned copy is made. Accept one transient non-zeroized `String` inside rig's header map for the dispatch lifetime. `CredentialCache`, the single-flight, the pre-send revocation fence, and `invalidate_binding` all stay; per-binding TLS-pool isolation is dropped (TLS session reuse carries no credential — auth is a per-request header). |
| F9 | Live conformance harness fate | **Delete.** `tests/live/aex-live-model-catalog`, the publisher/qualifier binaries, `model-catalog-qualify.yml`, the deepseek tokenizer oracle, and the orphaned `tokenizers` workspace dependency all go. rig version pinning replaces the conformance concept: rig upgrades are reviewed PRs and release events, not live-probed. |
| F10 | `aws-lc-rs` removal unlocks direct session-app dependency | **Accepted.** With `signature.rs` deleted, `aex-model-catalog` becomes pure Rust; `aex-session-app`'s copied `ModelQualifier`/`QualifiedModel` (ports.rs:550-618) is deleted and replaced by a direct dependency on the slimmed crate. |
| F11 | Workspace conventions (vendored + hash-pinned codegen, workspace-check rules, reqwest 0.13.4/rustls aws-lc-rs alignment) | **Confirmed by spikes.** rig-core pulls reqwest 0.13.4, tokio 1.53.1, rustls via aws-lc-rs (no `ring`), MIT license, compiles clean on 1.97.1. `rig`/`rig-core`/`rig-agent` must be added to `aex-workspace-check`'s vendor list so pure crates can never link them. |

## Revised decisions

1. **Adopt `rig` as the sole runtime transport authority.** Unchanged from the
   original. Delete the eight adapters, `sse`, `stream`, `budget`, `transport`,
   `pool`, `redact`, `build_identity`, and the `SendGate`/`DispatchProof`
   machine. The brain calls one thin rig-based `ProviderPort` implementation
   (`aex-brain-provider`).

2. **Vendor + hash-pin a models.dev snapshot; codegen.** Unchanged, with spike
   facts: snapshot 3,658,229 bytes, SHA-256 pinned (`sha256sum -c` + committed
   digest), no schema-version field — the hash is the version. Generator:
   TypeScript run with `bun` (~150 LOC), emitting a checked-in Rust module
   (801 rows, ~162 KiB) with `GENERATED_FROM_SHA256` embedded; CI runs the
   generator and `git diff --exit-code` to prove the committed table matches
   the pinned snapshot. Snapshot bumps are manual (`scripts/fetch-models-dev`
   helper, ~35 LOC): no cron, no PR bot — a maintainer commits the new
   snapshot and it rides the normal release train (second-round disposition
   9).

3. **The generated artifact is identity, limits, and admission.** Rows:
   `provider, model, context_window_tokens, max_output_tokens, tools,
   parallel_tools, dialect_class`. No capability matrix, no cost, no reasoning,
   no cache, no sampling, no retry metadata. models.dev `limit.output` is
   always present for the eight providers — admission refuses (no default) if
   it ever goes missing. `ModelId`/`ModelSlug` validation stays: the request
   string must hit the compiled set, so a typo fails fast at the boundary.

4. **Keep the brain and agent loop.** Unchanged. `ProviderPort`,
   `DispatchTicket`, durable effects, fences, cancellation, MicroVM tools,
   telemetry, and retained generation stay ours. rig's `Agent` is not adopted.

5. **Keep BYOK custody unchanged.** Unchanged, with the F8 hand-off shape:
   custody crates, the decrypted-key cache, and the revocation fence stay;
   the decrypted key is handed to rig by borrow at a per-dispatch client
   construction. The compile-time "adapter cannot see the credential"
   invariant is relaxed as accepted (the plaintext reaches a third-party
   library's header map for the dispatch lifetime; the leak-test suite moves
   to rig-shaped fixtures).

6. **No custom providers; route by dialect class.** Revised per F6: native
   modules for `openai`, `anthropic`, `google`; rig's OpenAI-compatible
   chat-completions path for `deepseek`, `zai`, `moonshotai`, `openrouter`,
   and `vercel_ai_gateway`, with base URLs from models.dev `api` when present
   and one compiled constant for vercel. No per-provider exceptions beyond
   that constant.

7. **Bounded retry, single-generation dispatch.** Revised. rig performs no
   request-level retry and its stream is zero-reconnect (F1), so the router
   owns the retry policy: re-issue a `Clone`d `CompletionRequest` (safe —
   `Clone`+`Serialize`, all-pub fields) through a fresh model handle, ≤3
   attempts, equal-jitter backoff, cancellable, for (a) definitive 429/503
   refusals (status + body readable via `provider_response_status()`), and
   (b) mid-stream transport drops (which surface as `ProviderError` with no
   status). Exhaustion returns a terminal `ProviderDispatchError`; the brain
   settles it and the run stops or succeeds. No infinite loops, no silent
   re-sends; the duplicate-generation risk of retrying a possibly-sent
   drop is accepted and recorded.

8. **Emergency disable: rebuild-and-redeploy for pre-launch.** Unchanged.

## Catalog trust: decision A confirmed

Full replacement of the signed-catalog authority, per the original decision A:
KMS signing key, OIDC publisher role, protected `model-catalog-publish.yml`
lane, last-good binding, predecessor chain, and the
`AEX_MODEL_CATALOG_BINDING_JSON` step in the `brain-mux` and
`session-stream-api` builds are all deleted. Admission becomes a compiled,
code-reviewed allowlist generated from the vendored snapshot. The `mc1_` catalog
revision survives as the blake3 of the vendored snapshot digest, so session
pins and the public wire contract are unchanged.

## Architecture shape after the change

- `aex-model-vocabulary` (new, pure) — `canonical`, `failure`, `primitives`:
  the provider-neutral vocabulary consumed by nearly every brain crate. The
  split keeps the vocabulary crate free of any catalog data.
- `aex-model-catalog` (slimmed) — the generated admit table, the thin
  `QualifiedModel` wrapper, a 2-bit `CapabilitySet`, and `admit()` with a
  **two-arm** `CatalogError` (`UnknownProvider`, `UnknownModel`); the
  `UnqualifiedProviderModel` arm and the public `unqualified_provider_model`
  error code (api/schemas/registries/errors.yaml) are deleted as a prelaunch
  clean cut. Deleted: `signature`, `collection`, `catalog`, `receipt`,
  `build_binding`, the heavy `document` schema, and `aws-lc-rs`.
- `aex-brain-provider` (new) — implements `ProviderPort` (whose `budget`
  parameter is removed — clean cut, including the mux's per-activation 1 MiB
  stream-buffer permit) and the production `CatalogPort` binding: dialect
  routing, pre-send admission and revocation fence, the bounded retry loop,
  canonical frame mapping, `mark_response_started` on the first stream item.
  Owns the decrypted-key `CredentialCache` + single-flight (consumer-side
  optimization; custody stays a stateless adapter). No interim-usage preview
  frames.
- `aex-brain-provider-custody` — absorbs the gateway's credential port
  definitions (`ProviderCredentialDirectory`, `ProviderCredentialDecryptor`,
  `ProviderCredentialBinding`, `ProviderApiKey`, `CredentialResolveError`)
  so the gateway can be deleted without breaking custody.
- `aex-session-app` — drops its `ModelQualifier` copy and the third refusal
  arm; depends on the slimmed catalog directly.
- Deleted: `aex-brain-provider-gateway`, `tests/live/aex-live-model-catalog`
  (the `aex-live-brain-mux` companion stays — verified it needs no provider
  keys, so all `AEX_LIVE_PROVIDER_KEY_*` envs die with the harness),
  `infra/modules/model-catalog-authority`, the platform composition root, and
  the two model-catalog workflows.

## Second-round dispositions (2026-08-13)

Owner decisions closing the review's open questions; they supersede the
"Open items" of the original proposal.

1. **Gateway admission is broad.** For `openrouter`/`vercel`, every
   `<upstream>/<model>` that models.dev lists is admitted — the regenerated
   gateway table *is* the allowlist, no per-upstream curation. `ModelId`
   validates against the compiled table; `/` and `~` ids are body fields
   only (spike-verified: the request path stays `/chat/completions`).
2. **Exhausted retries stop deterministically.** The router returns
   `DispatchStage::Terminal` when the bounded retry loop exhausts (429/503
   refusals and mid-stream drops alike), so the brain settles `KnownFailure`
   and the run ends `Failed` — retry, then stop or success. Proofs on the
   retry path: pre-send → `NotSent`, definitive non-2xx → `ResponseStarted`,
   drop → `PossiblySent`.
3. **rig stays exact-pinned.** rig 0.41.0 pinned; upgrades are ordinary
   reviewed PRs whose CI runs the adapter's mock-server golden suite. No
   canary process, no extra ceremony.
4. **No runtime catalog readiness.** The `catalog_verified` flag is deleted;
   `const _: () = assert!(!ALLOWLIST.is_empty())` replaces
   `is_service_capable`; CI owns digest correctness.
5. **Vocabulary split.** `aex-model-vocabulary` (pure: canonical, failure,
   primitives) and `aex-model-catalog` (generated table + admission).
   Mechanical import renames across consumer crates, prelaunch clean cut.
6. **`StreamBudget` removed now.** The `ProviderPort` `budget` parameter is
   deleted in this project, including the mux's 1 MiB stream-buffer
   admission permit (BR-59). No bounds anywhere; the adapter enforces none.
7. **New crate named `aex-brain-provider`.**
8. **No interim usage.** Preview frames carry no incremental usage; usage is
   final-only via rig.
9. **Snapshot refresh is manual.** No cron, no PR bot: the maintainer runs a
   small fetch-and-regenerate script, commits the snapshot + digest + table;
   CI verifies (sha256 + generator output match) and the change rides the
   normal release train.
10. **Emergency disable stays rebuild-and-redeploy** (decision 8, as-is);
    the procedure is recorded in `failure-response.md` at implementation.
11. **The unqualified arm is deleted.** `CatalogError` has two arms; the
    `unqualified_provider_model` wire code is removed from
    `api/schemas/registries/errors.yaml` and contracts regenerate.
